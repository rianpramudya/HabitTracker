## Keputusan teknis

- Tidak membuat grant/lisensi/data produk otomatis saat signup. Atas pilihan eksplisit pemilik 6 Oktober, akun allowlist dapat mengaktifkan akses personal development setelah persetujuan di UI. Ini pengecualian lokal; kepemilikan email belum terbukti dan tidak memenuhi gate beta/publik.
- ESLint memakai TypeScript/hook/a11y plugins langsung; eslint-config-next diganti setelah audit menemukan dependency rentan yang belum punya perbaikan. Vitest diperbarui ke versi yang sudah diperbaiki. Audit akhir nol vulnerabilities; bukan jaminan tidak ada kerentanan yang belum diketahui.
- Semua kanal nanti memanggil domain yang sama. Server-only privileged client dipakai untuk RPC commit dan aktivasi development yang memeriksa owner serta sesi; normal read lewat user client/RLS. Server secret tidak boleh masuk client bundle.
- Fondasi snapshot commit adalah baseline development; pagination/query granular, limits dataset dan operasional concurrency/load harus dilanjutkan sebelum beta/publik.

## Pekerjaan berikutnya dan blocker

Pengujian 6 Oktober memakai identitas **sintetis** di Supabase development: `read_core` ditolak sebelum aktivasi; aktivasi dengan sesi nyata berhasil; `read_core` setelahnya berhasil; `commit_core` menyimpan satu dompet dan pembacaan ulang menemukan barisnya; operasi dengan pemilik lain ditolak. Semua baris terkait dan identitas uji kemudian dihapus. Browser memeriksa form aktivasi mobile. Dua akun pemilik kini telah diaktivasi melalui UI untuk uji Feed; pengujian end-to-end pencatatan inti dengan kedua akun belum lengkap. Grant berakhir setelah tujuh hari; perpanjangan bukan otomatis. Ekspor di dashboard saat ini hanya mengunduh catatan yang termuat, belum memenuhi permintaan ekspor penuh/reauth pada PRD.

1. Migrasi/advisors/anonymous API smoke selesai. Server secret telah diterima dan pemeriksaan read-only berhasil. Integrasi auth berikutnya memerlukan konfigurasi signup aman dan status provider email/domain; kredensial berikutnya diisi langsung di `.env.local`, bukan chat.
2. Fondasi auth fase 4: tentukan/konfigurasi alur signup publik aman (AC23), SMTP/domain/delivery, OTP policies, CAPTCHA/rate-limit terdistribusi, password/session controls, verified setup dan cleanup. `/api/account` hanya membuka signup/login/logout pada development lokal untuk email allowlist; aksi lain tetap 503. Jangan menyalakan AUTH_READY hanya karena akun development berhasil masuk.
3. Implementasi akses/onboarding/prefs nyata, safe unpaid/revoked shell, consent versions, reauth export/delete, account recovery/email change; provision session guards/grants lewat operasi administratif terotorisasi dan audit.
4. Hubungkan core ke data nyata setelah syaratnya aman; catalog kategori/metode, actual fasting range/start-end, activity timestamps, pagination dan histori target lanjut. Preview bukan pengganti penerimaan module penuh.
5. Tooling admin/moderator/support, MFA, audit workflows, cleanup/rate jobs, support hak data.

Sebelum Feed ON pada beta/cohort, selesaikan kebijakan dan operasi moderasi/banding, privasi/retensi, verifikasi email/auth aman, dukungan unblock yang mudah, uji multiuser langsung dan gate §23/§26–27 PRD.

Changelog markdown Supabase gagal dibaca via web; dokumentasi resmi SSR/RLS dibaca, tetapi perubahan provider harus diverifikasi lagi saat konfigurasi nyata. Skills yang diterapkan: Next.js, Supabase, frontend-design, UI/UX, React review dan browser/testing verification.

## Pembaruan Feed development — 6 Oktober 2026

Perluasan profil Feed: halaman `/feed/people` untuk pencarian nama anggota aktif dan `/feed/profile/[id]` untuk membuka profil dari posting; pemilik dapat mengubah nama serta memasang/menghapus foto profil PNG/JPEG/WebP. Foto sumber maksimal 12 MB dipotong di browser menjadi WebP 320 px dan payload tersimpan dibatasi 512 KB. Migrasi `social_profiles` diterapkan ke proyek development. Foto disimpan sementara pada tabel privat dan dikirim melalui endpoint yang memeriksa sesi, akses Feed, serta blokir dua arah. Posting pribadi tidak muncul pada profil orang lain. Media pada posting tetap ditunda sesuai PRD; penyimpanan/retensi foto untuk beta masih perlu keputusan. Tes database sintetis mencakup pencarian, visibilitas profil, foto, blokir, dan konflik revisi nama. Build, lint, typecheck, dan 42 tes lulus. Browser headless memastikan pengguna tanpa sesi diarahkan ke login tanpa error JavaScript; halaman dengan sesi nyata belum diuji di browser pada perubahan ini karena tidak memakai kredensial atau meniru akun pemilik. Ini belum menyatakan Feed siap rilis publik.

Perbaikan editor foto 6 Oktober 2026: pemrosesan lama mewajibkan hasil `canvas.toBlob('image/webp')` benar-benar WebP, padahal browser dapat mengembalikan PNG jika format itu tidak didukung. Pemilihan foto kini membuka dialog dengan geser/zoom dan preview, lalu ekspor JPEG dengan fallback PNG saat Simpan. Batal tidak mengirim request. Pada gagal upload, foto lama tetap ada dan dialog menunjukkan error; pada berhasil, versi avatar baru langsung dirender. Penyimpanan tetap melalui `private.social_avatars` dan RPC berizin, **bukan Supabase Storage**; proyek development belum mempunyai bucket Storage. Uji browser sintetis mencakup file tidak valid, crop/zoom, Batal, gagal upload, dan sukses upload melalui respons API simulasi; uji database mencakup isolasi akun dan foto lama tetap ada setelah input gagal. Request langsung tanpa sesi ke endpoint upload mendapat HTTP 403. Empat screenshot editor sintetis mobile/desktop terang/gelap ada di `docs/screenshots/avatar-editor-*`; keempatnya tanpa overflow horizontal/error JavaScript. Uji unggah end-to-end memakai sesi akun pemilik nyata belum dilakukan pada perubahan ini. Penyimpanan biner di Postgres tetap keputusan development sementara.

Migrasi `social_foundation` berhasil diterapkan ke proyek development. Grant tabel `social_posts` untuk anon/authenticated tidak ada; RPC sosial hanya dapat dipanggil service role. Advisor menampilkan INFO `rls_enabled_no_policy` pada tabel sosial yang memang default deny, serta WARN leaked-password protection yang sudah ada sebelumnya. Pengujian domain/database termasuk dua akun sintetis, privasi, blokir, laporan, moderasi, dan penolakan akses langsung. Browser pada server development terisolasi membuktikan daftar → aktivasi → bergabung → publish → reload tetap tersimpan. Screenshot Feed mobile/desktop terang/gelap ada di `docs/screenshots/social-feed-*`. Pengujian ini memakai identitas sintetis dan tidak mengaktifkan Feed pada server normal.

Uji dua akun pemilik menemukan RPC `social_feed` gagal dengan `42501 permission denied for table users` ketika membaca posting komunitas penulis lain. Tes database sebelumnya menjalankan fungsi sebagai pemilik skema sehingga melewatkan kasus service role. Migrasi `social_author_access` menjadikan lookup boolean `private.social_author_active` sebagai `SECURITY DEFINER` di skema tidak terekspos, tetap dengan `search_path=''` dan EXECUTE hanya untuk service role. Tes baru menjalankan feed sebagai service role; sebelum migrasi gagal dengan kesalahan yang sama, sesudahnya lulus. Panggilan PostgREST nyata untuk akun kedua kini berhasil; anon/authenticated tetap tidak dapat mengeksekusi lookup atau SELECT langsung `social_posts`. Dua akun masih perlu diuji ulang lewat browser milik pemilik setelah memuat ulang halaman.
